# File formats

## ROOT (the POLAR layout, the default)

A response file is a flat ROOT file of TH1 histograms keyed `sim_{energy:03d}_{pol:03d}_{angle:03d}`: `energy` is the photon energy in keV, `pol` the polarization degree in percent (000 unpolarized, 100 fully polarized), `angle` the polarization angle phi0 in integer degrees. `sim_200_000_000` is the unpolarized ASAD at 200 keV and `sim_200_100_045` the fully polarized ASAD at 200 keV with phi0 = 45 degrees. The histogram axis is the measured azimuthal scattering angle eta in degrees. The key template is a Python format string (`key_template` of `PolarRootAdapter`); output histograms are written with weighted storage so the propagated per-bin errors survive (needs the `hist` package). Reading and writing need `uproot`. A POLAR response holds, per energy, 61 unique simulations: one unpolarized and 60 fully polarized at 3 degree steps from 0 to 177 degrees.

## FITS tables

One binary-table extension per ASAD with the columns ETA_LO, ETA_HI (degrees), COUNTS and ERROR, header keywords ENERGY (keV), POLFRAC, POLANG (degrees), DELTA and LAMBDA (the source incidence, degrees) and MENHAGV (the package version), and extension names `ASAD_{energy:04d}_{pol:03d}_{angle:03d}` mirroring the ROOT keys. This is a plain self-describing table layout, not an OGIP response. Needs `astropy`. When the input file given to `FitsAdapter` is a `.prsp` response instead, the adapter detects it from its extensions and reads it as described in the next section.

## CSV

Long format, one file. Input columns `energy, bin_low, bin_high, counts`, optional `error`, and for mode 2 input rows `pol` (percent) and `angle` (degrees). Rows of one ASAD tile the azimuth contiguously in increasing `bin_low`. Output columns `energy, pol_fraction, pol_angle, bin_low, bin_high, counts, error`. Needs `pandas`. The shipped `examples/sample_data/ideal_detector_asads.csv` is in the input schema.

## The .prsp polarization response of polpy

The `.prsp` file is the layout read by the polpy plug-in for threeML (the format document of the threeML/polpy repository): INEBOUNDS (the Monte Carlo energy bin edges), INPAVALS (the polarization angles of the polarized entries), SABOUNDS (the scattering-angle bins), and the two image extensions SPECRESP POLMATRIX (energy by polarization angle by scattering angle, fully polarized) and SPECRESP UNPOLMATRIX (energy by scattering angle). The package reads it through `PrspAdapter` (or `FitsAdapter`, which detects it) and writes it with `menhag.adapters.convert_prsp(events_root, rmfarf_root, out_path, layout=...)` from a ROOT response, with `PrspAdapter.save_response` from a build, or with `write_response_prsp` from a `ResponseSet`; `menhag build` exports one through the io keys `prsp_output` and `rmfarf_path` (ROOT input) or `format: prsp`. Needs `astropy`, and `uproot` for the ROOT paths.

Two plug-ins have read this layout, and they disagree on which polarized entry belongs to which angle, so the package names the layout by the plug-in that reads it. In the `polpy-1.2.1` layout, that of the current polpy release, entry j of the polarized matrix is the ASAD simulated at INPAVALS[j]; this is the order of the format document and of the response files the POLAR collaboration delivers, and it is the default of every writer, because it is what the current plug-in reads. In the `polarpy` layout, that of the earlier plug-in behind the fits of the accompanying paper, entry j holds the ASAD at 180 - INPAVALS[j] degrees, the mirror image along the angle axis; the fits of the paper used that earlier plug-in with response files in this order. A fit against a file in the wrong order returns the polarization angle reflected through 90 degrees and leaves the polarization fraction untouched. Every writer records its layout in the header keyword PALAYOUT of the INPAVALS and SPECRESP POLMATRIX extensions and every reader honours it; a file without the keyword is read in the layout named by the `layout` argument, or in the default layout with a logged warning. The option is `layout=` of `convert_prsp` and `write_response_prsp`, `output_layout=` of `PrspAdapter`, the io key `prsp_layout` and the flag `--prsp-layout` of `menhag build`.

The export writes the angle labels 0 to 180 degrees at 3 degree steps, 61 entries: the 60 polarized simulations from 0 to 177 degrees and a 180 degree entry that is a copy of the 0 degree ASAD, the closed boundary polpy expects, since the polarization angle is defined modulo 180 degrees. The energy grid of the file comes from the instrument's RMF/ARF ROOT file (the ER_low and ER_high histograms; for POLAR, 150 bins from 5 to 750 keV) or, for `PrspAdapter`, from the input file. The header keywords TELESCOP and INSTRUME default to the POLAR values of the paper and are parameters of every writer.
